## Training method

Everything so far is **PPO fine-tuning** via `examples/finetune_deterministic.py` in
`--soft-reward` mode: the reward is a soft detection probability per node (`P_fused`),
fused from an audio classifier and a camera (YOLO) detector, rather than a hard 0/1 hit.

Two-stage recipe that produced the current best:

**Stage 1 — base checkpoint (run 227):** train PPO from scratch, audio-only fusion, topo
random-walk movement prior, 400 iterations. This is the common starting checkpoint for all
fusion ablations (`runs/agent_run227_ppo`).

```bash
track_mdp_env/bin/python examples/finetune_deterministic.py \
    --env iobt --scratch --new-run 227 \
    --soft-reward --fusion-mode audio \
    --iobt-prior topo \
    --iobt-gt-session 20250812_165739 \
    --pooled-clf results/pooled/pooled_clf_20260521_164149.pkl \
    --iterations 400
```

**Stage 2 — camera-fusion fine-tune (run 236, current best):** fine-tune from run 227 using
camera-only fusion (`P_cam` — camera detections are much cleaner than audio for this
session) with a *softened* reward scale.

```bash
track_mdp_env/bin/python examples/finetune_deterministic.py \
    --env iobt --run 227 --new-run 236 \
    --soft-reward --fusion-mode camera \
    --soft-scale 0.8 --soft-threshold 0.4 \
    --iobt-gt-session 20250812_165739 \
    --pooled-clf results/pooled/pooled_clf_20260521_164149.pkl \
    --gps-eval \
    --iterations 200
```

### What's been tried (see `experiments/index.md` for full table)

| Finding | Runs |
|---|---|
| Audio-only fusion plateaus at ~68% — signal too weak/noisy for RL gradient | 228 |
| Camera-only fusion is the strongest single mode, ~90% | 229, 233 |
| `or_max` / `weighted` / `cam_fallback` fusion all re-introduce audio noise, no better than camera-only, and `or_max`/`cam_fallback` **degrade after ~iter 130** | 230, 231, 232, 238, 239 |
| `soft-scale` sweep: 1.5 no better than 1.2; **0.8 is best found so far** (91.00%) — weaker/smoother reward reduces training oscillation | 235, 236 |
| Chaining a fine-tune from an already-best checkpoint **regresses** (overfits) — don't fine-tune from run 229/236 again, always branch from the 227 base | 234 |
| Generalization to a different session (`20250812_091600`) is poor — accuracy drops to ~70% even from the best camera checkpoint | 237, 240 |
| Longer base pretraining (500 vs 400 iters, run 241) raised eval accuracy to 99% on its own but only marginal gain (~90.15%) once camera-fused (run 242) — diminishing returns so far | 241, 242 |

### Next steps toward 95% (untried, ranked by likely payoff)

1. **Sweep `--soft-scale` below 0.8** (e.g. 0.5, 0.6, 0.7) from the run 227 base with
   camera fusion — the 1.2→0.8 trend was monotonically positive and wasn't bottomed out.
2. **Multi-session training** — every fusion run so far trains and evals on the single
   session `20250812_165739`. Combine `20250812_165739` + `20250813_154313` (+ the
   `20240806_*` sessions) into one soft-reward training set to reduce overfitting to one
   trajectory and improve the accuracy ceiling, not just generalization.
3. **`--advanced-hparams`** flag (slow-convergence PPO: lr=1e-4, batch=4000, entropy=0.01,
   clip=0.2, grad_clip=30) has never been tried on the camera-fusion runs — worth an
   ablation against the current default PPO hyperparameters.
4. **Combine `--node-clfs-dir` binary gating with `--soft-reward` camera fusion** — these
   two mechanisms have only been used separately so far (binary gating was used in the
   6-node classifier pipeline in `CLAUDE.md`, not in the 10-node soft-reward runs 227-242).
   Gating soft camera detections by a confirmed binary classifier hit might cut false
   positives that cap accuracy below 95%.
5. **Use the run 241 base (500-iter topo prior, 99% raw eval accuracy) as the source for
   a full soft-scale sweep**, not just the single scale=1.2 pass done in run 242 — run
   241→242 only tested one config from the better base.
6. **Re-run the `cam-fallback-thresh` sweep** (only 0.0 and 0.65 tested in run 232/238) —
   intermediate thresholds (e.g. 0.3, 0.5) weren't tried and cam_fallback peaked
   competitively (89.95%) before degrading.
7. **Establish a `--gt` oracle upper bound** (drives both training and eval from GPS
   ground truth directly, bypassing classifiers entirely) to check whether 95% is even
   achievable given the current sensor/classifier noise floor, before spending more
   compute on RL hyperparameter tuning.

### Rules learned the hard way (don't repeat)

- Don't chain a fine-tune from a checkpoint that's already the best in its lineage —
  it overfits and regresses (see run 234).
- Don't trust a single-session eval number as a generalization measure — runs 237/240
  show it can collapse ~20 points on an unseen session.
- Log every run in `experiments/run{N}/notes.json` and re-run `experiments/make_notes.py`
  so `experiments/index.md` stays the single source of truth — don't let ad-hoc runs go
  unlogged.
